# Architecture

Status: Phase 1, 2026-11-02. The kit/site split, theme runtime and registry follow Patina UI's ([its architecture](https://github.com/ossianravn/patina-ui/blob/main/docs/architecture.md)); this document owns what differs: the pen engine, drawings and their takes.

## Repository layout

```
src/fineliner/            # the kit: everything a consumer installs
  pen/                    # framework-free engine: seed, filters, geometry, stroke (the pen), layers (sheets and
                          #   blanks), shapes, library (object registry), scenes, drawing-svg, glyphs,
                          #   lettering-svg, pen-marks
    objects/              # the drawings: one file per part of a collection, each registering its objects with
                          #   define(); an entry module per collection (indie, food, studio, people, everyday),
                          #   index (all of them) and rooms (the kit's four scenes); units and parts are shared
  drawing/                # React: <Drawing>, <Lettering>, <PenMark>, <Circled>, and drawing-motion (settle, draw-on)
  styles/                 # fineliner.css (Tailwind entry) and the files it imports: fonts, tokens, stocks, pens,
                          #   textures.generated, roles, base, frames, drawing
  theme/                  # appearance state, pre-paint script, useAppearance
  defs/                   # <FinelinerDefs>: the shared wobble filters
  lib/                    # cn
src/site/                 # layouts, the specimen sections, the appearance panel, the desk
src/pages/                # / (specimen), /drawings, /desk
specimen/                 # the static style prototype; the reference until everything is ported
tools/paper/              # the paper generator: writes styles/textures.generated.css
tools/registry/           # the registry builder: writes registry.json and public/r/
tools/check-contrast.mjs  # every pen against every textured stock
tests/consumer/           # the registry install contract
```

## The pen engine

`src/fineliner/pen/` has no React and no DOM, and ESLint keeps it that way. It renders at build time, in the browser and (later) in share images, and the same seed gives the same SVG everywhere.

- **`pen(seed, hand, take)`** draws strokes: each is resampled every 3px and offset along its normals by slow eased noise plus a faint tremor; open strokes run past or stop short of their ends; circles go a little past where they started. `hand` is `calm` or `lively`. Paths are written by `pathOf()` (`path.ts`): points rounded to tenths as relative steps (`M12.3 4l3 -.1 2.9 0`), each step between rounded points so nothing drifts, about half the bytes of absolute pairs; `pathPoints()` and `pathBox()` read any M/L/H/V/Z path back.
- **`sheet(id)`** collects paths in layers. `blank(d)` hides everything drawn before it inside a shape with a mask (the paper still shows through), so a figure stands in front of a wall line. One mask per layer, never nested: nested masks made the first prototype too slow to paint. A layer's mask holds only the later blanks whose box meets the layer's own (with 12 units of room for the pen line); markup whose paths cannot be read counts as reaching everywhere. Before this every layer carried every later blank, so a scene's masks grew with the square of its layers (the room scene was 3.3 MB in three takes; it is 560 KB). Mask ids come from the drawing's seed and take, so server and browser agree.
- **The library** (`library.ts`): `define()` registers objects; `place()` draws one into a sheet with its own fork of the seed. An object draws its composition from `r`, the `shape` stream, and its lines from `p`, the pen. Objects are typed `Draw` functions; `DrawOptions` lists every choice a caller may fix instead of the seed.
- **Scenes** (`scenes.ts`) compose objects back to front inside the drawn border. A scene may also be drawn **open** (`format`: `wide`, 1600 by 860, or `tall`, 800 by 900; `boxed` is the default): no border, the floor running past both edges, the lamp hung from above the sheet, the left of the wall kept clear for a page's text, so the room becomes part of a page section rather than a picture beside it. A scene offers its open formats in `open` (each a size and a composer on a `stage()` of that size, named `<scene>:<format>` so masks never clash when both are on one page); `sceneIn()` picks the size and composer and falls back to boxed. A page shows the wide room on wide containers and the tall one on narrow ones, both drawn at build time and switched in CSS, since nothing measures; `hero-01` crops the wide one like a photograph (as wide as its section or as tall, whichever covers it, the floor at the bottom). `<Drawing>` carries `data-format`, so the browser draws the other takes in the same format.
- **Collections install and register on their own.** The engine (`@/fineliner/pen`) registers no drawings. A collection registers when its entry module is imported (`import "@/fineliner/pen/objects/indie"`), every collection with `@/fineliner/pen/objects`, and the kit's scenes with `@/fineliner/pen/objects/rooms`; each is a registry item (`drawings-indie` … `drawings-everyday`, `drawings-all`, `scenes`), so a project installs and bundles only the drawings it shows. Collection files never import each other; what two collections share (`units.ts`, `parts.ts`: the flowerpot, the leaf, the mug) belongs to the engine. The library and the scenes live on `globalThis` under `Symbol.for` keys, one per realm, because a framework may load the engine twice (Next.js renders server and client components from separate copies of a module): a collection a server component imports is then drawn by the client `<Drawing>`'s copy during the server render. Kit parts import what they draw (the blocks with rooms import `rooms`, the avatar `people`), so their items depend on it. In the browser, a page whose drawings render without React passes `boilTakesIn()` a loader for its collections, which runs only when boil first needs another take. Decided 2026-11-03, when the library reached 85 objects and the engine's browser chunk had grown to 32 KB gzipped.
- **A project's own drawings.** A consumer registers objects with `define()` under any collection name and scenes with `defineScene()`, built on the exported `stage()` (walls, rug, border, `put`), from its own module (`src/drawings/`), so updating the kit through `shadcn add` never overwrites them. The engine exports the shapes (`box`, `pad`, `banded`, `drum`, `cylinder`, `sprig`) for this, and `@/fineliner/pen/objects/people` the people parts (`clothes`, `TOPS`, `HAIR`, `head`, `hairBehind`). The drawing skill (`skills/fineliner-drawings`, registry item `drawing-skill`) teaches a coding agent to do it in the kit's style; its `scripts/render.mjs` renders contact sheets through jiti and sharp or a headless Chrome or Edge.
- **`drawing({ object | scene, seed, hand, takes, title })`** returns one SVG per take. **`lettering(text, { face, seed, hand, takes })`** draws words from the skeleton alphabet as Tramline SVG from a seed (MÅLTID's wordmark, so no Tramline font loads there); `<Lettering>` sets the fonts instead. Fineliner Naïve Sans, the first display font, is a real font built from the same skeleton by `tools/fonts/build.mjs` (`npm run build:fonts`): strokes wobbled, swept by a round pen and merged into outlines (polygon-clipping), fitted with cubic curves, three takes per glyph rotating through `calt`, kerning as a GPOS table, written as OTF and WOFF2 (`public/fonts/`) and embedded in `styles/line-sans.generated.css`. Fineliner Naïve Inline and its Fill come from the same build (`tools/fonts/inline.mjs`: a broad-nib contrast rule, double lines for thick parts, the tint as a second font) and are embedded in `styles/inline.generated.css`, its own registry item (`font-inline`), since together they weigh 160 KB; the site loads them from `/fonts/`. Fineliner Naïve Tramline (`tools/fonts/tramline.mjs`) draws each skeleton stroke as three parallel lines 32 units apart, each wobbled on its own and run past or short of its ends, swept by a pen 13 units wide, with a seeded tilt and lift per take; it is 243 KB as WOFF2, so it is opt-in too (`styles/tramline.generated.css`, registry item `font-tramline`). `tools/fonts/family.mjs` writes any family: three takes rotating through `calt`, kerning, and line metrics pinned in OS/2, and for a Bold, Italic or Bold Italic the weight class, fsSelection, macStyle and italic angle that link it to its Regular. Every face is built in four styles: Bold with a broader pen, Italic with the skeleton slanted 10° about half the cap height before the pen draws it, both with the Regular's seeds; their stylesheets are `*-styles.generated.css`, each its own opt-in registry item, and the site loads them from `/fonts/` (`src/site/site.css`), so a page fetches a style only where it sets it. The curve fitter (`tools/fonts/fit.mjs`) splits a section whose fitted handles reach further than its points, since its error is measured only at the points. The build is deterministic. **`penMark(name, seed)`** draws the small interface marks.

### Takes

A take is the same drawing with another pen: the pen forks by `take:n` while the composition streams stay put, so takes differ only in the line. Three takes stack in a `.fl-takes` span; `styles/drawing.css` cycles them for line boil (`data-boil`, nearest element wins) and `settleDrawing()` plays them once after a reroll. Only the first take is named for screen readers. The server sends only the first take, so a page carries each drawing once (decided 2026-11-03: the other two were most of what the long pages weighed). `drawing-takes.ts` draws the second and third in the browser where boil can show them: in idle time, one take at a time, for drawings in view when boil runs always or on hover (the default) with a pointer that can hover, and both at once under the pointer. A touch screen has no hover, so there a tap (a pointer that lifts where it came down, not a scroll) draws both and boils the drawing once: two rounds of its takes at the boil's pace (`--take`), resting on the first. With boil off or under reduced motion they are never drawn, and the pen engine (23 KB gzipped) never loads; on a phone it loads at the first tap on a drawing. `<Drawing>` registers itself; a page whose drawings render without React in the browser calls `boilTakesIn()` once (the site's layouts do). The `<span>` carries `data-seed`, `data-object` or `data-scene`, and `data-hand` for this; `still` leaves the seed off. A drawing drawn in the browser, as after a reroll, has all three takes at once.

### Determinism rules

JavaScript engines may differ in the last bit of `Math.sin`, `Math.cos`, `Math.hypot` and `**`. A last-bit difference in a length can change how many points a stroke gets, which shifts every random draw after it. So:

- Lengths use `Math.sqrt` (every engine rounds it the same way), never `Math.hypot`.
- Nothing uses `**` or `Math.pow`; a curve that needs a power uses a polynomial.
- `snap()` rounds coordinates and lengths to hundredths before they decide a count.
- Composition never comes from the pen, so takes cannot drift apart.

## Rendering in the page

- **Frames are CSS** (`frame`, `rule`, `ink-fill`, `pen-shadow` in `styles/frames.css`) with seeded custom properties from `frameVars(seed)`, so they render on the server and nothing measures (decision S6).
- **Drawings are inline SVG** from `drawing()`: in Astro at build time with no script, memoized in React islands. Pen lines use `vector-effect: non-scaling-stroke`, so every line is the pen's weight at any size. A hydrating `<Drawing>` keeps the server's markup instead of drawing every take again (`useSyncExternalStore` tells hydration from a browser render, and React leaves inner HTML alone when it hydrates); it draws in the browser once a prop changes, as on a reroll.
- **Draw-on** (`drawOnView`) never hides what the server sent: a page shows its pictures without waiting for its script. When `drawWhenSeen()` arrives, a drawing already in view stays as it is; one out of view is hidden there (`fl-unseen`, the whole SVG at opacity 0, since a zero-length dash with a round cap still paints a dot) and drawn on when it comes into view. A drawing drawn in the browser (an empty state that appears, a reroll) waits undrawn from its first paint. On a phone the script arrives one to two and a half seconds after the text, and the scenes used to wait for it (as a scatter of dots, then whole at 2.5 s). `drawWhenSeen()` draws the first take stroke by stroke when it comes into view and shows the other takes when it has finished. It measures every stroke in screen pixels before animating any (non-scaling strokes ignore `pathLength`; measuring after each `animate()` laid the page out once per stroke, half a second for the room scene on a slow phone). Under reduced motion it appears at once.
- **The paper** is split by cost (`styles/base.css`): the grain (tooth, relief, mottle), whose SVG filters are slow to rasterize, lies on a fixed `html::before` as tall as the largest viewport and is painted once; the specks (flecks, fibres) lie over it on `body` and scroll with the page. A screen of 1.5 dppx or more takes the sharp flecks (`--tex-flecks-sharp`), the same specks held to about a pixel across: a 1x screen rounds a speck under a pixel up to a soft whole pixel, and a dense one draws it true to size, where it vanishes. When all five layers lay on the root, they were rasterized again wherever the page changed: a collapsible opening dropped every other frame. Small surfaces take the whole stack (`--paper-texture`).
- **The site serves Naïve Sans as a file.** The kit embeds the font in its stylesheet; `astro.config.mjs` points the built stylesheet's `@font-face` at `/fonts/` instead and the layouts preload it, so the render-blocking stylesheet is 51 KB gzipped rather than 126 KB.

## Registry

`npm run registry` writes `registry.json` and `public/r/*.json` from `src/fineliner/` (Patina's builder, adapted); `npm run registry:check` fails when they are stale. Membership is in `tools/registry/items.json`: `base` (styles, theme, defs, `lib/utils`, and the engine files defs needs: `pen/seed`, `pen/filters`), `pen` (the rest of the engine, without drawings), one item per collection (`drawings-indie`, `drawings-food`, `drawings-studio`, `drawings-people`, `drawings-everyday`), `drawings-all`, `scenes` (the kit's rooms), `drawing` (the React components) and the umbrella `fineliner`. New files in `pen/` or `drawing/` join their item without editing the builder. Rules carried from Patina: every kit file installs at the same path under `src/fineliner/`; basenames are unique, because `shadcn add` rewrites imports by file name; imports are read in either quote style, CSS `@import`s included. New here: the builder refuses a `base` file that imports another item.

`npm run test:consumer` builds the registry into a temporary folder, serves it, installs `drawing`, `drawings-indie` and the other listed items into a copy of `tests/consumer/fixture/` through the real shadcn CLI with npm offline, and asserts byte-identical files, a clean type-check and a build.

## Theme runtime

As Patina's, with Fineliner's attributes on `<html>`: `data-theme` (and `data-theme-preference`), `data-stock` (bond, the default; recycled, kraft), `data-pen` (navy, black, sepia, forest, oxblood, custom; the custom pen's `penHue` and `penStrength` go on as `data-pen-hue`/`data-pen-strength` and as the `--pen-hue`/`--pen-strength` properties its CSS reads, clamped to `PEN_MIX`), `data-hand`, `data-boil` (off, hover, art), `data-containers` (open, boxed), `data-labels` (caps, type) and `data-density`. `appearanceScript()` applies the saved choice before first paint; `useAppearance()` reads and writes it. Both, with `readSaved`, `save` and `AppearanceControl`, take an optional storage key, for two sites on one origin that keep their own looks. Any element can set `data-pen`, `data-hand`, `data-boil` or `data-labels` for its subtree (and `--pen-hue` for a custom pen of its own). The site's appearance panel (`src/site/appearance-panel.tsx`) opens from every page's header, Listening Room's, and MÅLTID's demo strip (with MÅLTID's defaults, its own look as the first preset and its own key), as a sheet that is not modal over an undimmed page. MÅLTID's strip also has "Show parts" (`src/site/parts-xray.tsx`): it finds kit parts by shadcn's `data-slot`, names each once (a trigger after what it opens) and links its docs page. It is the site's, so it may measure the page.

## Deployment

The `Dockerfile` builds the static site and serves it with nginx (`deploy/nginx.conf`) as the `frontend` app of the Fineliner project in Dokploy, on the ByteHosting server (109.71.252.137), rebuilt on every push to `main`, at https://naiveindieline.com. `www` redirects to the apex; Traefik issues the certificates, and the domain is proxied by Cloudflare (the server only admits Cloudflare on 80 and 443). The registry JSON ships with the site under `/r/`, readable from any origin, and the share images under `/og/`. nginx serves each page at one URL without a trailing slash, as Astro builds them, and `404.html` for anything missing; hashed assets under `/_astro/` cache for a year. `astro.config.mjs` sets the canonical URL; the `SITE_URL` build argument overrides it.
